State-Aware Interruption: Formulas and Derivations

Nov 3, 2026 · @Barath Suresh

Revised Nov 5, 2026 to match the Phase 2 classifier in src/classifier: one stuck score sts_tst​, flow defined as 1−st1-s_t1−st​.

Overview

The agent speaks only when the chance its offer is accepted clears a bar, and that bar moves with the user's state: higher in flow, lower when stuck. Four quantities feed one rule. The Phase 2 classifier turns recent activity into one stuck score from 0 (flow) to 1 (stuck), and flow is its complement. Two yes/no questions to the model give the chance help is needed and the chance an offer would be accepted. The gate compares them and picks speak, wait, or quiet.

The gate is PRISM's Bayes-risk threshold (Fu et al., ICLR 2026). The new part is that its two costs are functions of user state instead of constants. Everything works without an LLM: the probabilities can come from any model, including a logistic regression or a constant.

Pipeline: the classifier gives the stuck score sts_tst​. The two probes give pneedp_{\text{need}}pneed​ and pacceptp_{\text{accept}}paccept​. The gate turns sts_tst​ and pneedp_{\text{need}}pneed​ into one bar τt\tau_tτt​, compares pacceptp_{\text{accept}}paccept​ with it, and picks speak, wait or quiet.

State only enters through the costs. A wait loops back and the whole gate re-runs with fresh scores at the next natural break.

1. State score (the Phase 2 classifier)

State comes from the classifier in src/classifier, not from a separate flow detector. It produces one number per tick: st∈[0,1]s_t \in [0,1]st​∈[0,1], where 0 is flow and 1 is stuck. No LLM is involved. The code is the source of truth: if a value here disagrees with features.py, scorer.py or weights.json, the code wins.

Clock and window. One tick every Δ=5\Delta = 5Δ=5 s. Features look back over a time window of W=60W = 60W=60 s (not a count of events, because typing is a rate and window switches are minutes apart). Three features use a longer memory, listed in the table.

Clip function. clip(x)\mathrm{clip}(x)clip(x) keeps a value inside 0 to 1:

clip(x)=min⁡(1,max⁡(0,x))\mathrm{clip}(x) = \min(1, \max(0, x))clip(x)=min(1,max(0,x))

Every feature is causal: it uses only what was known at that tick. A window visit counts only after 2 s, a command only after it finishes, and AFK only after the watcher's 180 s timeout.

Flow is the complement

The classifier scores one axis, so there is no separate flow score:

stuckt=st,flowt=1−st\mathrm{stuck}_t = s_t, \qquad \mathrm{flow}_t = 1 - s_tstuckt​=st​,flowt​=1−st​

The damper flow′=flow (1−stuck)\mathrm{flow}'=\mathrm{flow}\,(1-\mathrm{stuck})flow′=flow(1−stuck) from the earlier draft is dropped. With complementary scores it would count stuck twice. The "both high" problem it fixed cannot happen.

Paused or away

The classifier does not set flow and stuck to 0 when the user is away. It pauses scoring and freezes sts_tst​ when any of these holds:

Reason Meaning
no_input no input events cover the tick
no_window no window event (a sleeping laptop)
meeting a meeting app is in front
afk the AFK watcher reports away (known only after 180 s)
locked lock screen

While paused, the gate makes no decision: no probes, no speaking. After 1800 s of pause, sts_tst​ resets to σ(b)\sigma(b)σ(b), so a coffee break does not wipe the score but a long absence does. Quiet staring at the screen is still scored, because the stalling feature reads it. If the user returns to the same error, revisits and repeats raise sts_tst​ on their own.

Using the score to save LLM calls

The probes of section 2 run only when the cheap score is high enough:

st≥θtrig(0.10 with hooks,  0.19 without)s_t \ge \theta_{\text{trig}} \quad (0.10 \text{ with hooks}, \; 0.19 \text{ without})st​≥θtrig​(0.10 with hooks,0.19 without)

Below θtrig\theta_{\text{trig}}θtrig​ the gate stays quiet without calling the model.

Fitting the weights

The weights are hand set. To fit them, use a logistic regression on the same ten features, still LLM-free, with the same form as rtr_trt​. Fit on the labels, cross-validated by person (the repo splits people, not days: dev people 1 to 14, test people 15 to 20). Use different labels for fitting and for evaluation.

2. Confidence probes and calibration

The gate needs two calibrated probabilities. Use two questions, not one, because PRISM's ablation shows that using acceptance alone raised false alarms to 62.5%, while using both signals kept them at 22.9%.

Probe Question asked Gives
Need "Does the user need help right now? Answer yes or no." pneedp_{\text{need}}pneed​
Accept "If you offered help now, would the user accept it? Answer yes or no." pacceptp_{\text{accept}}paccept​

From the model's answer to a probability

Read the log-probabilities of the tokens "yes" and "no" (lyesl_{\text{yes}}lyes​, lnol_{\text{no}}lno​) and normalize over just those two:

p=eℓyeseℓyes+eℓno=σ(ℓyes−ℓno)p = \frac{e^{\ell_{\text{yes}}}}{e^{\ell_{\text{yes}}} + e^{\ell_{\text{no}}}} = \sigma(\ell_{\text{yes}} - \ell_{\text{no}})p=eℓyes​+eℓno​eℓyes​​=σ(ℓyes​−ℓno​)

Why two tokens only: the model also puts probability on other tokens ("Yes", spaces, punctuation). Renormalizing over yes and no turns the answer into a proper binary probability.

Resampling for borderline cases

When logprobs are unavailable, or p is near the bar, sample the answer k times at temperature above 0 and use the share of yes:

p^=1k∑j=1k1[answerj=yes],SE(p^)=p^(1−p^)k\hat{p} = \frac{1}{k}\sum_{j=1}^{k} \mathbb{1}[\text{answer}_j = \text{yes}], \qquad \mathrm{SE}(\hat{p}) = \sqrt{\frac{\hat{p}(1-\hat{p})}{k}}p^​=k1​j=1∑k​1[answerj​=yes],SE(p^​)=kp^​(1−p^​)​​

With k = 5 the standard error near p = 0.5 is about 0.22, wider than the 0.1 wait margin. Use k ≥ 10 if the share is the main signal (standard error about 0.16), or prefer logprobs.

Temperature calibration

Raw model probabilities are usually over- or under-confident. Rescale the log-odds by one constant per probe:

p^=σ ⁣(logit(p)T)\hat{p} = \sigma\!\left(\frac{\mathrm{logit}(p)}{T}\right)p^​=σ(Tlogit(p)​)

T < 1 makes probabilities more extreme, T > 1 pulls them toward 0.5, and T = 1 changes nothing. Fit T on a held-out labeled set by minimizing the negative log-likelihood:

T∗=arg⁡min⁡T>0  −∑i[yiln⁡p^i(T)+(1−yi)ln⁡(1−p^i(T))]T^{*} = \arg\min_{T > 0} \; -\sum_{i} \Big[ y_i \ln \hat{p}_i(T) + (1 - y_i) \ln\big(1 - \hat{p}_i(T)\big) \Big]T∗=argT>0min​−i∑​[yi​lnp^​i​(T)+(1−yi​)ln(1−p^​i​(T))]

Here yiy_iyi​ is 1 if help was needed (hotkey press or chatbot visit soon after), else 0. Fit TneedT_{\text{need}}Tneed​ and TacceptT_{\text{accept}}Taccept​ separately. PRISM found TneedT_{\text{need}}Tneed​ = 0.5 and TacceptT_{\text{accept}}Taccept​ = 0.7 for its model; yours will differ.

Why it matters: in PRISM's no-calibration ablation, a need-dependent threshold scored F1 70.3 against 80.7 for a fixed 0.5 cut. A moving bar only helps if the probabilities feeding it are honest.

Safety clip

Keep probabilities away from exactly 0 and 1 so the threshold and log-odds stay finite:

p←min⁡(1−ϵ,max⁡(ϵ,p)),ϵ=10−3p \leftarrow \min(1 - \epsilon, \max(\epsilon, p)), \qquad \epsilon = 10^{-3}p←min(1−ϵ,max(ϵ,p)),ϵ=10−3

3. The gate: why the threshold has this form

Speak when the expected cost of speaking is lower than the expected cost of staying silent. This is the Bayes-optimal rule under asymmetric costs (PRISM, Appendix A), and the threshold follows from it in four lines.

Step 1: list what can go wrong. Correct decisions cost 0.

Action Goes wrong when Probability Cost
Speak The offer is not accepted 1 − pacceptp_{\text{accept}}paccept​ CFAC_{\text{FA}}CFA​
Stay silent Help was needed and would have been accepted pneedp_{\text{need}}pneed​ · pacceptp_{\text{accept}}paccept​ CFNC_{\text{FN}}CFN​

The silent row multiplies the two probabilities, which assumes need and acceptance are independent given the context. PRISM makes the same assumption.

Step 2: expected cost of each action.

E[cost∣speak]=(1−paccept) CFA\mathbb{E}[\text{cost} \mid \text{speak}] = (1 - p_{\text{accept}})\, C_{FA}E[cost∣speak]=(1−paccept​)CFA​

(1−paccept) CFA≤paccept pneed CFN(1 - p_{\text{accept}})\, C_{FA} \le p_{\text{accept}}\, p_{\text{need}}\, C_{FN}(1−paccept​)CFA​≤paccept​pneed​CFN​

The same rule in log-odds

Divide both sides of Step 3 by (1 − pacceptp_{\text{accept}}paccept​) · pneedp_{\text{need}}pneed​ · CFNC_{\text{FN}}CFN​ and take logs:

logit(paccept)≥ln⁡CFA−ln⁡CFN−ln⁡pneed\mathrm{logit}(p_{\text{accept}}) \ge \ln C_{FA} - \ln C_{FN} - \ln p_{\text{need}}logit(paccept​)≥lnCFA​−lnCFN​−lnpneed​

This form shows what each input does in one line. The bar in log-odds is a sum of three terms, so each one pushes independently. It is also the form the state-aware costs in section 4 plug into most cleanly.

Why this formula and not a fixed cut

  • It is derived, not chosen. Any other rule has a higher expected cost under the same costs and probabilities.
  • The costs are interpretable knobs. CFAC_{\text{FA}}CFA​ : CFNC_{\text{FN}}CFN​ says how many false alarms you would trade for one missed moment of help.
  • It is PRISM's gate. Using it unchanged keeps the comparison to the base paper clean, so any gain comes from the state-aware costs alone.

The last point carries a condition: the gate is optimal only when the costs are right. PRISM fixes them for the whole session, and its authors list that as a limitation. Section 4 removes that limitation.

4. State-aware costs (the contribution)

Use multiplicative (log-linear) costs as the main form. They turn the whole gate into one sigmoid of a sum, so every knob has a meaning that does not depend on the others.

CFA(st)=c0 eα⋅flowt,CFN(st)=m0 eβ⋅stucktC_{FA}(s_t) = c_0 \, e^{\alpha \cdot \mathrm{flow}_t}, \qquad C_{FN}(s_t) = m_0 \, e^{\beta \cdot \mathrm{stuck}_t}CFA​(st​)=c0​eα⋅flowt​,CFN​(st​)=m0​eβ⋅stuckt​

The reasoning is the office-colleague argument from the methodology. Interrupting deep focus is costlier than usual, so CFAC_{\text{FA}}CFA​ grows with flow. Missing someone who is stuck is costlier than usual, so CFNC_{\text{FN}}CFN​ grows with stuck. With α = β = 0 both costs are constant and the gate is exactly PRISM's.

The full gate in one line

So the bar rises with focus (low sts_tst​), falls when stuck (high sts_tst​), and falls with need, for every value of the other inputs. The simulation in section 6 confirms this on a grid for both cost forms.

What α and β mean

At full flow, false alarms cost e^α times their base. At full stuck, misses cost e^β times their base. So set them from a plain statement:

α=ln⁡kflow,β=ln⁡kstuck\alpha = \ln k_{\text{flow}}, \qquad \beta = \ln k_{\text{stuck}}α=lnkflow​,β=lnkstuck​
Statement Value
"Interrupting full flow is 3 times worse than usual" α = ln 3 ≈ 1.10
"Missing a stuck user is 2 times worse than usual" β = ln 2 ≈ 0.69

These are starting values to tune on held-out days.

Only the sum α + β matters

Because flow = 1 − s, the gate depends on the state only through one slope and one offset:

Why wait exists: a near miss in flow usually means help is likely needed but this moment is costly. Dropping the offer throws away a likely need, and speaking now pays the flow cost. Waiting for a cheaper moment avoids both.

PRISM uses the same margin δ for a different purpose: to trigger an extra slow reasoning pass near the bar. You can use both. A near miss can first get a resample (section 2), and only a near miss that survives it is deferred.

Natural break and re-check

A wait creates a pending offer. Re-run the whole gate, with fresh state scores and probes, at the first natural break:

  • typing stops for at least 5 seconds after a burst
  • a window switch
  • a file save or a commit

At a break, flow is usually lower, so the bar has dropped. If pacceptp_{\text{accept}}paccept​ now clears it, speak. If not, the offer stays pending.

6. Does it work? Checks run on these formulas

With a reliable state signal, the state-aware gate roughly halves unwanted interruptions during flow at the same recall as PRISM's fixed gate. With an unreliable signal it does harm. These results come from the script verify_formulas.py: exact checks plus 40,000 synthetic decision points per setting.

Scope after the classifier change. That simulation drew flow and stuck as two separate signals. The classifier gives one score with flow = 1 − s, so the "flow-only" and "stuck-only" rows below no longer isolate separate signals (see "Only the sum α + β matters" in section 4). Rerun verify_formulas.py with sss drawn from the classifier's measured distribution (section 1) before quoting any number from this section.

What the synthetic test assumes. Need is rare in flow (8%), common when stuck (60%), and 25% otherwise. That is the methodology's hypothesis, built in. The test therefore shows the formulas do what they are designed to do. It is not evidence that real users behave this way, which is what your own data must show.

What this means for the method

  1. The method protects focus. With a clean signal, flow false alarms drop by 44% at recall 0.80 and by 46% at 0.90.
  2. It moves interruptions rather than removing them. Overall precision falls by about 8 points. To keep recall the same while staying quiet in flow, the gate speaks more often at other times. Report this next to the headline metric, or a reviewer will find it.
  3. The flow term carries the gain. Flow-only matched the full gate on flow false alarms (0.48% vs 0.48% at recall 0.80). Stuck-only barely moved them (0.82%). In this test stuck needs were already caught 98% of the time, so the stuck term mainly matters at lower recall settings.
  4. Signal quality decides everything. With a noisy signal the gain shrinks, and at recall 0.90 it reverses. With a meaningless signal, flow false alarms almost double. This is why the go/no-go check on the state scores has to come before the cost logic.
  5. Calibration is fixable and necessary. Making pneedp_{\text{need}}pneed​ overconfident (log-odds × 2.5) dropped the fixed gate's precision from 0.57 to 0.39. Temperature scaling fitted on held-out data recovered T = 2.50, the injected distortion, and restored precision to 0.58. The state-aware gate kept its flow advantage in all three cases (0.67%, 0.60%, 0.70% vs 1.19%, 1.12%, 1.26%).

Pass criteria for real data

Keep the state-aware gate only if it passes all four on held-out days:

  • [ ] Stuck score predicts help-seeking: AUROC clearly above 0.5 against hotkey presses and chatbot visits
  • [ ] sts_tst​ thresholded at θtrig\theta_{\text{trig}}θtrig​ agrees with human flow/stuck labels better than chance (Cohen's kappa well above 0)
  • [ ] Fewer flow interruptions than the calibrated fixed gate at matched recall
  • [ ] Precision loss reported, and small enough to accept

Uncertainty

Report 95% confidence intervals by bootstrap over days (or users), 10,000 resamples, as PRISM did over events. Resample whole days, not single events, because events within a day are correlated. Tune all parameters on separate days from those you evaluate on, and leave one user out when you have several.

8. Open issues and caveats

  • PRISM's paper disagrees with itself. Equation 3.1 and the Appendix A derivation give τ = CFAC_{\text{FA}}CFA​ / (CFAC_{\text{FA}}CFA​ + pneedp_{\text{need}}pneed​ CFNC_{\text{FN}}CFN​), which is the form used here and re-derived in section 3. Appendix B states the code's default as τ = CFNC_{\text{FN}}CFN​ q / (CFAC_{\text{FA}}CFA​ + CFNC_{\text{FN}}CFN​ q), which rises with need instead of falling. The printed odds form (A.2) also reads pacceptp_{\text{accept}}paccept​ / (1 − pacceptp_{\text{accept}}paccept​) ≥ pneedp_{\text{need}}pneed​ CFNC_{\text{FN}}CFN​ / CFAC_{\text{FA}}CFA​, the inverse of what the derivation gives (≥ CFAC_{\text{FA}}CFA​ / (pneedp_{\text{need}}pneed​ CFNC_{\text{FN}}CFN​)). Check their released code before claiming equivalence, and say in the paper which form you use.
  • Independence assumption. The silent-cost term pneedp_{\text{need}}pneed​ · pacceptp_{\text{accept}}paccept​ assumes need and acceptance are independent given context. A user who needs help may also be more willing to accept it, so this can understate the miss cost.
  • Costs are relative, not measured. CFAC_{\text{FA}}CFA​ and CFNC_{\text{FN}}CFN​ encode a preference between the two mistakes, not seconds or dollars. That is why every result should show a sweep over c0c_0c0​ : m0m_0m0​ (PRISM used 1:4 to 1.2:1).
  • The cost form is a modeling choice. Nothing in PRISM or the data says costs are exponential or linear in state. Section 6 shows the two give near-identical results, so keep the additive form as an ablation.
  • The simulation is circular by design. It assumes the hypothesis to test the math. Only real hotkey presses, chatbot visits and human labels can show the method helps people.
  • The precision trade-off is real. At matched recall the state-aware gate lowered overall precision by about 8 points in simulation. The paper should report it beside interruptions per flow-hour.
  • The score is not a probability. sts_tst​ is an EMA of a hand-weighted logistic. It is monotone in stuckness but it is not calibrated, and it is spread out on stuck ticks (a quarter stay below 0.06). The cost formulas use it as a 0 to 1 intensity, and α and β absorb the scale. If you want a calibrated state, apply temperature scaling to logit(st)\mathrm{logit}(s_t)logit(st​) on held-out labels, as for the probes.
  • Flow is the complement. There is no independent flow signal, so the gate cannot tell "focused" from "merely not stuck". The earlier draft's separate flow score (typing bins, switches, saves) is dropped, and typing has weight 0 in the classifier.
  • The state evidence is synthetic. Every number about sts_tst​ comes from our own generator, which also made the labels.
  • All start values need tuning. Window length, caps, signal weights, α, β, δ, θflow\theta_{\text{flow}}θflow​, cooldown and wait expiry are starting points, tuned on held-out days.
